# DistKV Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Raft-based, fault-tolerant, linearizable distributed key-value store in Go, from scratch, with chaos testing, honest benchmarks, and production-shaped ops tooling.

**Architecture:** Raft core is pure logic with `Storage` and `Transport` injected as interfaces. Production uses bbolt storage + gRPC transport; tests use in-memory storage + an in-process fault-injecting network simulator. The KV state machine applies committed log entries. Linearizable reads use ReadIndex.

**Tech Stack:** Go 1.26, gRPC + protobuf, bbolt, testify, `pgregory.net/rapid` (property tests), `tview` (TUI), Prometheus client, Docker, Kubernetes, Helm, GitHub Actions.

## Shared Types (defined once, referenced everywhere)

These signatures are authoritative. Later tasks must match them exactly.

```go
// internal/raft — core types
type NodeID string

type Role int
const ( Follower Role = iota; Candidate; Leader )

type LogEntry struct {
    Term  uint64
    Index uint64
    Type  EntryType // EntryNormal | EntryConfChange | EntryNoop
    Data  []byte    // serialized Command or ConfChange
}

type HardState struct { CurrentTerm uint64; VotedFor NodeID }

type Snapshot struct {
    Index uint64
    Term  uint64
    Conf  Config   // membership at snapshot point
    Data  []byte   // serialized store state
}

type Config struct { Voters []NodeID; // joint consensus:
    OldVoters []NodeID; Joint bool }

// Storage — persistence interface (raftstore + memstore implement it)
type Storage interface {
    LoadHardState() (HardState, error)
    SaveHardState(HardState) error
    AppendEntries([]LogEntry) error          // appends, truncating conflicts
    Entries(lo, hi uint64) ([]LogEntry, error)
    LastIndex() (uint64, error)
    Term(index uint64) (uint64, error)
    FirstIndex() (uint64, error)             // 1 + snapshot index
    SaveSnapshot(Snapshot) error
    LoadSnapshot() (Snapshot, error)
    Compact(upto uint64) error               // discard log <= upto
}

// Transport — RPC interface (grpcTransport + simnet implement it)
type Transport interface {
    Send(to NodeID, msg Message) (Message, error)
}

// Message — unified RPC envelope
type MsgType int
const ( MsgRequestVote MsgType = iota; MsgRequestVoteResp;
    MsgAppendEntries; MsgAppendEntriesResp;
    MsgInstallSnapshot; MsgInstallSnapshotResp )
type Message struct {
    Type MsgType; From, To NodeID; Term uint64
    // RequestVote
    LastLogIndex, LastLogTerm uint64; VoteGranted bool
    // AppendEntries
    PrevLogIndex, PrevLogTerm, LeaderCommit uint64
    Entries []LogEntry; Success bool; ConflictIndex, ConflictTerm uint64
    // InstallSnapshot
    Snapshot *Snapshot
    // ReadIndex piggyback
    ReadID uint64
}

// internal/store — state machine
type Command struct { Op OpType; Key, Value string; ExpectValue string }
type OpType int
const ( OpPut OpType = iota; OpDelete; OpCAS )
```

gRPC service surface (`api/distkv.proto`): `RaftService.Step(Message)` for
internal RPC; `KV` service with `Put`, `Get`, `Delete`, `CAS`, `Status`,
`AddNode`, `RemoveNode`.

### Task 4.3: Leader election
**Files:** Create `internal/raft/election.go`, `internal/raft/election_test.go`.
- `Tick()` on follower/candidate increments election elapsed; on timeout → `becomeCandidate`, send `MsgRequestVote` to peers. Handle `MsgRequestVote` (grant iff term ok + not voted + candidate log up-to-date) and `MsgRequestVoteResp` (majority → `becomeLeader`). Higher term anywhere → `becomeFollower`.
- [ ] Test (3 in-memory nodes wired via `simnet`, driven by `Tick`): exactly one leader elected within bounded ticks; split vote resolves on retry; isolated node never wins. Implement. Commit `feat(raft): leader election`.

### Task 4.4: Log replication
**Files:** Create `internal/raft/replication.go`, `internal/raft/replication_test.go`.
- `Propose(data []byte) (index uint64, err error)` (leader-only). Leader sends `MsgAppendEntries`. Follower handler: term/prevLog checks, append+truncate conflicts, set `ConflictIndex/Term` on mismatch for fast backoff, advance `commitIndex` to `min(LeaderCommit, lastNewIndex)`. Leader handler: on success advance `matchIndex/nextIndex`, recompute `commitIndex` as the highest N replicated to a majority **with `term[N]==currentTerm`** (§5.4.2); on failure decrement via conflict hint.
- `Ready() []LogEntry` returns newly-committed entries to apply.
- [ ] Test: propose on leader → entry committed on all 3 nodes; follower with divergent tail gets it repaired; commit only advances for current-term entries; entry not committed when only a minority is reachable. Implement. Commit `feat(raft): log replication and commitment`. Push phase.
